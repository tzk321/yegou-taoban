### 1．高：棱镜拦弹范围明显大于可见镜面
**位置：**`tickBullets()`、`newDashGear()`。

镜面是横向约±25、纵向±66的多边形，实际拦截却为：
```js
segmentDistance(prismWall.x,prismWall.y,ox,oy,b.x,b.y)<b.r+58
```
这是圆形拦截区。例如同高度、横向距镜心50的弹心，即使弹体未碰到镜面，也可能被清除；镜面上下尖端附近则可能漏挡。与“实体经过镜面才拦截”不一致。

**最小修复：**以实际镜面多边形做扫掠圆碰撞；或把绘制和碰撞统一成同一个矩形/胶囊体，避免独立手填58。

### 2．高：敌弹图形与伤害半径不一致
**位置：**`BULLET_PROFILES`、`bulletArt()`、`tickBullets()`。

例如`spectrum`半径11，但横线伸到−24；`train`半径15，图形横向伸到−22。碰撞始终使用`b.r+27`，且旋转不改变碰撞体。因此可见尖端可以穿过玩家判定边缘而不伤害。空心`ring`又按实心圆处理，中心没有实体笔画也可接触结算。外层低透明圆同样不与判定半径重合。

**最小修复：**明确“实体核心”和纯装饰范围；让实体图形严格落在统一圆判定内，并显示对应实体圆，或为各形状配置与绘制一致的碰撞几何。玩家的半径27也应有可核对的可见身体依据。

### 3．中：BGM旧节点回调会误减新一轮节点计数
**位置：**`note().onended`、`stopMusic()`。

`stopMusic()`清空集合并把`musicNodes`置0，但旧振荡器的`onended`仍会异步到达。若已启动新主题，旧回调仍执行：
```js
musicNodes=Math.max(0,musicNodes-1)
```
从而扣掉新主题的计数，出现`active`小于`scheduled`甚至有声音而`active=0`。这是计数错误，**不能据此断言实际音轨叠加**。

**最小修复：**
```js
o.onended=()=>{
  o.disconnect(); g.disconnect();
  musicVoices.delete(v);
  musicNodes=musicVoices.size;
};
```
最好直接移除独立可漂移计数，快照使用集合大小。

### 4．中：清场未清除警告缓存，可能清空后不重画
**位置：**`clearBullets()`、`renderBulletWarnings()`。

`clearBullets()`只`replaceChildren()`，保留`data-v53`。后者只有缓存键改变才重建内容。在同键下清场后重新渲染，警告层会保持空白。非Boss分支也清空内容而不移除缓存键。当前代码没有保证每次重新进入警告场景时键必然不同。

**最小修复：**集中封装警告清理，同时执行：
```js
g.replaceChildren();
g.removeAttribute('data-v53');
```
两个警告容器均如此处理。

### 5．中：阶段清场只清敌弹，技能与反击残留没有明确策略
**位置：**`stepBulletBoss()`末尾及`clearBullets()`。

进入`phaseChange/defeated`时仅清敌弹和事件；`prismWall`、`landArmed`、回响视觉及`shots`仍保留。`updateDashMotion()`还会在阶段转换期间继续调用`tickNewGear()`。因此上一阶段留下的镜子、二段跳落地武装可能跨到下一阶段；旧反击也继续追踪移动Boss，即使最终被窗口序号拒绝。

**最小修复：**在“进入阶段”的单一入口清除敌弹、反击实体、镜子、落地武装及技能视觉。不要顺手重置`lastRailDash`；若技能CD要求跨阶段保留，也不要直接调用会将`echoCool=0`的现有`clearNewGear()`，应拆分“清实体”和“重置CD”。

### 6．中：rail时间戳在冲刺获准前提交
**位置：**`dashCore()`前缀替换。

新前缀先写`lastRailDash`、追加历史，再执行原函数剩余内容。若原函数内部因冷却、阶段或其他条件拒绝冲刺，8秒账本仍可能被消耗。所贴源码缺少剩余函数体，无法判断具体拒绝路径，但提交顺序确实不安全。

**最小修复：**保留8秒检查在入口，将时间戳写入移到所有准入检查之后、真正开始冲刺的位置。所有路线共用该入口；继续保留独立时间戳，不能只依赖可被旧逻辑清零的`S.cool`。

### 7．低：方向键别名共享身份，释放一个会停止另一个
**位置：**`initV53()`键盘监听。

A和左箭头都以`'keyboard'`加入左集合。按住二者，再释放任意一个，就删除唯一身份；另一个仍按住却停止左移。D/右箭头同理。

**最小修复：**用`e.code`作为集合身份，按下、释放一致；失焦仍统一清空。

### 必须补齐证据的审查项
- **TDZ：**模块`let`先初始化、后调用`initV53()`本身不能认定有TDZ。仍须核对更早插入的`catalog-v53.js`处，`LEGEND_SKINS`和`CATALOG`已完成初始化；“在存档白名单之前”不等于“在声明之后”。
- **HUD/反击可达：**新布局自身未见按钮坐标直接越界；但缺SVG层级、原HUD坐标、焦点处理，不能确认移动后无遮挡。另`keydown`在目标属于`.button`时直接返回，会使获得按钮焦点后的F/方向键失效，应只排除文本输入控件。
- **单钱包/全Boss实体伤害：**补丁没有新增钱包，但未提供旧存档校验、全部伤害调用点及道场入口；不能仅凭同名函数替换就确认旧档无损或所有模式都无残留伤害路径。
